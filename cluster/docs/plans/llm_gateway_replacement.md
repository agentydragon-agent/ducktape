# LLM gateway replacement requirements

This records the current LiteLLM contract for a later replacement review. It describes
requirements and gaps from the checked-in configuration; it does not compare products.
`Must` means a deployed caller or control-plane workflow currently depends on it. `Should`
means it is configured and useful but not exercised by every caller. `Nice` marks retained,
historical, or inactive capability. The current custom proxy image pins
`litellm[proxy]==1.103.0`; older investigation notes can describe behavior observed under
1.100.1. [requirements.in:1-6](../../../tana/litellm_proxy/requirements.in#L1)

The owner reports current use of the Claude and Codex subscription lanes. Additional provider routes
may be of interest if they are cost-effective. The inventory also records routes used by other callers.

## Langfuse fields and paths

The current proxy config explicitly selects `langfuse_otel` and `prometheus`; Langfuse
project keys and the OTEL host are supplied to the pod. With those keys present, the legacy
callback writes its own observations as well as the OTEL integration. The June tracing note
observed a `GENERATION` `litellm_request`, a `SPAN` `raw_gen_ai_request`, and corresponding
OTEL `events_full` rows for the same Responses trace. Langfuse v4 is now configured for
`events_only` / `direct` ingestion. [proxy.py:160-182](../../cdk8s/litellm/proxy.py#L160),

## Current pain points

- **Responses trace content reaches pod logs.** [#5761](https://github.com/agentydragon/ducktape/issues/5761) reports the root observation input/output is now populated on a successful streamed Responses request, but the deployed OTel v2 default console exporter serializes captured prompt content to stdout. Keep Langfuse delivery while removing this log exposure.
- **The historical z.ai failure is a separate path.** The June note's `glm-4.6` `/v1/responses` failure was a LiteLLM Responses-to-chat bridge path configured with `use_chat_completions_api=true`; it is not evidence that current ChatGPT Responses traces fail. z.ai is absent from the current route roster. [Tracing note:26-40,73-104](../../debug/2026-06-05-litellm-responses-langfuse-otel.md#L26)
- **Model naming still has compatibility edges.** [#4823](https://github.com/agentydragon/ducktape/issues/4823) captures earlier name confusion and coordinated caller/key migrations. Current routes use provider/wire/model names, but retained aliases and client pins still make route renames cross-cutting. [catalog.py:6-66,751,755-779](../../../model_catalog/catalog.py#L6)
- **Provider prefix preprocessing can block health handlers.** A public `chatgpt/` alias invoked LiteLLM's synchronous interactive auth before router selection and caused an actual liveness restart. The deployed `chatgpt-sub/` prefix is the mitigation; stale callers can still trigger the old path. [liveness lesson:5-47](../lessons_learned/2026_10_22_litellm_chatgpt_alias_liveness.md#L5)
- **Crossplane provider changes are part of the gateway's operational surface.** The key ownership move required a patched provider for root-scoped Keys and write-only key state, plus ordered Tofu teardown, ESO exports, and a separate BuildBuddy sync. The recovery note records that the patched provider was installed and all 12 Keys and three Teams were Ready at its 16:07 UTC check; it also documents the Team deletion cascade and write-only-key reconciliation hazards. [crossplane debug:1-9,30-40](../../debug/2026_10_22_litellm_crossplane.md#L1), [provider package pin](../../cdk8s/crossplane.py#L28), [provider build workflow](../../../.github/workflows/crossplane-provider-litellm.yml)
- **Cost does not equal subscription billing.** LiteLLM and Langfuse estimates are useful for token/model attribution, but flat-rate ChatGPT/Claude subscription routes do not incur the displayed per-token bill. [props config.toml:47-61](../../../props/deploy/config.toml#L47), [litellm-claude.nix:18-20](../../../nix/home/claude_code/litellm-claude.nix#L18)
- **Langfuse v4 changed its ingestion layout.** The migration is complete on `events_only` / `direct`; a replacement must preserve trace and event ingestion under the current Langfuse deployment, not assume the prior observation tables are the only query surface. [migration note:1-3](../../debug/langfuse_v4_migration_20261022.md#L1)
