# Large Web Corpus Debundle Profile, 2026-05-26

Snapshot of the latest debundle perf profile against a private
consumer corpus. This doc is a living baseline — when the pipeline
gets new perf wins, edit it in place rather than starting a new file.

The current snapshot reflects three perf landings:

1. `lowering::exports::trim_dead_named_specifiers` O(N·M) →
   O(N+M) via precomputed `HashSet<&str>` (commit `21bdb8467`,
   released as `debundle-f461dd3f2de0`).
2. `write_tree_reports` JSON: `to_writer_pretty` → `to_writer` for
   the manifest writers (commit `894d435a7`).
3. `DirectoryDependencyEdgeManifest`'s per-edge
   `BTreeMap<String, usize>` → sorted `Vec<(String, usize)>`
   (commit `5fdb13353`).

A Nix-specific perf-wrapper fix (`edc2a218b`) is in this profile run's
build pipeline but does not affect debundle runtime cost: it swaps
GNU `addr2line` for `llvm-addr2line` during symbolization, cutting
the bazel action wall-time from 30-50 minutes to ~93 seconds and
restoring fast iteration on Rust DWARF profiles.

## What's hot now

### #1 hotspot: `emit_browser_harness::materialize_artifact_scripts::write_tree_reports`

```
emit_browser_harness                                  (11.47%)
└── materialize_artifact_scripts                      ( 7.27%)
    └── write_tree_reports                            ( 5.67%)
        ├── build_directory_dependency_manifests      ( 2.55%)
        │   ├── DirectionalDirectoryAccumulator::add_fact (0.64%)
        │   ├── directory_ancestors_for_file          ( 0.57%)
        │   └── module_path_dirname                   ( 0.51%)
        └── serde_json escape + write paths           (~2.5% via
            serialize_str + format_escaped_str)
```

The new hot leaves inside `write_tree_reports` are the per-edge
accumulator (`DirectionalDirectoryAccumulator::add_fact`) plus path
manipulation (`directory_ancestors_for_file`, `module_path_dirname`).

### Redundant `analyze_chunk` across consumers

`analysis::facts::analyze_chunk` is called multiple times per chunk:

```
materialize_logical_chunk
  → compute_stage_one_analysis           (4.00%)
    → analyze_chunk                      (2.75%)
sweep_unreachable_top_level              (7.26%)
  → analyze_prune_items                  (3.99%)
    → analyze_chunk                      (2.57%)
```

The Stage A composer's whole point was to compute `ChunkFactAnalysis`
once per chunk; `sweep_unreachable_top_level` re-runs the analysis on
the same chunk. Same story for `ChunkCodeGraph::build_full` (5.06%
standalone, reached from both code paths).

### serde_json string escaping

`serialize_str` (3.91%) + `format_escaped_str` (3.85%) ≈ ~7.5%
inclusive — JSON escape work on every key + string value in the
emitted manifests. For our payloads (binding names, module paths,
file paths) almost none of the input characters need escaping; the
serde_json fast path still checks each character against the escape
set.

## Recommended next perf target

**Dedup `analyze_chunk` across the Stage A composer and the
vendor-strip pipeline.** Plumb the `StageOneAnalysis.fact_analysis`
(or the underlying `ChunkFactAnalysis`) into
`sweep_unreachable_top_level` / `analyze_prune_items` so they consume
the cached chunk analysis instead of recomputing it.

Rationale:

1. **Cheapest large win.** ~3-5pp Children% combined; pure plumbing
   (no algorithmic change); the data is already computed once.
2. **Aligns with Stage A's stated invariant.** The composer's role is
   "compute the spec-independent chunk analysis once" — today that
   invariant is violated by every downstream consumer that re-analyzes.
3. **Unblocks further dedup.** Once `analyze_chunk` is threaded as
   shared state, `ChunkCodeGraph::build_full` (5.06% standalone)
   naturally dedupes too because it's a sub-computation of the facts.

Beyond that:

- **`build_directory_dependency_manifests` micro-optimizations**
  (2.55% Children): memoize `directory_ancestors_for_file` /
  `module_path_dirname` (same paths repeat across many edges);
  switch `DirectionalDirectoryAccumulator::add_fact` to a bulk-add
  for adjacent edges sharing prefixes.
- **SWC codegen `emit_with` tree** (sum ~22% inclusive across many
  tiny entry points): distributed across so many call sites that
  micro-optimization here is unlikely to dent the total. Better
  approach is reducing the _amount_ of code we re-emit through SWC
  — e.g. detect unchanged module bodies and skip codegen.
- **JSON escape fast path**: out of scope until the above land.
