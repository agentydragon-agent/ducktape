# Large Web Corpus Debundle Profile, 2026-05-26

Snapshot of the latest debundle perf profile against a private
consumer corpus. This doc is a living baseline — when the pipeline
gets new perf wins, edit it in place rather than starting a new file.

The current snapshot reflects three perf landings:

1. `lowering::exports::trim_dead_named_specifiers` O(N·M) →
   O(N+M) via precomputed `HashSet<&str>` (commit `21bdb8467`,
   released as `debundle-f461dd3f2de0`).
2. `write_tree_reports` JSON: `to_writer_pretty` → `to_writer` for
   the manifest writers (commit `894d435a7`).
3. `DirectoryDependencyEdgeManifest`'s per-edge
   `BTreeMap<String, usize>` → sorted `Vec<(String, usize)>`
   (commit `5fdb13353`).

A Nix-specific perf-wrapper fix (`edc2a218b`) is in this profile run's
build pipeline but does not affect debundle runtime cost: it swaps
GNU `addr2line` for `llvm-addr2line` during symbolization, cutting
the bazel action wall-time from 30-50 minutes to ~93 seconds and
restoring fast iteration on Rust DWARF profiles.

### Two `analyze_chunk` calls — but not redundant

`analysis::facts::analyze_chunk` shows up twice per chunk:

```
materialize_logical_chunk
  → compute_stage_one_analysis           (4.00%)
    → analyze_chunk                      (2.75%)
sweep_unreachable_top_level              (7.26%)
  → analyze_prune_items                  (3.99%)
    → analyze_chunk                      (2.57%)
```

The two calls _look_ redundant but are not. They differ on all three
inputs:

1. **Module state.** Stage A analyzes the pre-lowering entry-file AST.
   By the time vendor strip runs, `lower_chunk` has rebuilt the entry
   body, `apply_partial_vendor_swaps` has rewritten it, and
   `split_top_level_var_decls` + `strip_export_specifiers` have mutated
   it in place. The body fed to `analyze_prune_items` is structurally
   different from the one fed to Stage A.
2. **Hints policy.** Stage A runs with spec-derived purity hints and
   `LocalEffectPolicy::KnownEffectsOnly`. Vendor strip runs with empty
   hints and `LocalEffectPolicy::VendorPrune`, which materially changes
   `collect_local_effects` (VendorPrune folds `local_effect_targets`
   into every item's set; `KnownEffectsOnly` does not).
3. **Source-path / line-index.** Stage A carries them for diagnostics;
   strip does not.

`ChunkCodeGraph::build_full` (5.06% standalone) is parameterized by
the same purity hints, so it's not dedup-able either.

A real dedup would need one of: changing Stage A to use `VendorPrune`
(widens local-effects everywhere; needs a Stage A consumer audit);
running Stage A on the post-lowering module (creates a dependency
cycle — Stage A's atomic-units feed `lower_chunk`); or splitting
`analyze_chunk` into policy-independent sub-passes that can be shared
alongside policy-dependent passes that re-run. None are "pure plumbing."

### serde_json string escaping

`serialize_str` (3.91%) + `format_escaped_str` (3.85%) ≈ ~7.5%
inclusive — JSON escape work on every key + string value in the
emitted manifests. For our payloads (binding names, module paths,
file paths) almost none of the input characters need escaping; the
serde_json fast path still checks each character against the escape
set.

## Recommended next perf target

**`build_directory_dependency_manifests` memoization** inside
`write_tree_reports`. Concrete wins, in order:

1. **Memoize `module_path_dirname`** (0.51% solo). Each edge resolves
   its source + target file's parent dir. The same module paths show
   up across many edges — a per-path cache (HashMap keyed on the
   interned path) cuts the call count drastically.
2. **Memoize `directory_ancestors_for_file`** (0.57% solo). Same
   pattern: the ancestor chain of any given path doesn't change
   within one report build. Compute once per unique path.
3. **Bulk-add for adjacent edges sharing prefixes.**
   `DirectionalDirectoryAccumulator::add_fact` (0.64% solo) is called
   once per edge. Edges with a shared source/target directory could
   be coalesced into a single bulk-add.

Together: ~1.5-2pp Children% expected, achievable with a few HashMap
inserts and minor refactor. No semantic change.

Other targets, lower leverage:

- **SWC codegen `emit_with` tree** (sum ~22% inclusive across many
  tiny entry points): distributed across so many call sites that
  micro-optimization is unlikely to dent the total. Better approach is
  reducing the _amount_ of code we re-emit through SWC — e.g. detect
  unchanged module bodies and skip codegen entirely.
- **`analyze_chunk` partial dedup**: split into policy-independent
  sub-passes (`top_level_item_views`, `compute_shadowed_globals`)
  that can be shared between Stage A and vendor strip, and
  policy-dependent passes (`collect_local_effects`,
  `ChunkCodeGraph::build_full`) that re-run. Substantial refactor of
  `analyze_chunk` internals — probably not worth it until other
  cheaper wins are exhausted.
- **JSON escape fast path**: needs a custom Serialize wrapper that
  asserts "ASCII-safe, skip per-char check." Possible but invasive;
  defer.
